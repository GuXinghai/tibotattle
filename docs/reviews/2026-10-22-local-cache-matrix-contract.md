# 本地轮次缓存复用图修复

范围：用户截图中上方缓存连续性金额可用、灯阵提示证据不可用的故障。
基线为 `94cc26f3a63fc12b726fd47da8a83b44ba27e425` 及现有未提交改动。
这属于模型请求缓存分析，与应用计算结果复用是不同链路。
保留负载卡片预览及既有改动，不写真实数据、不提交、打包、重启或安装。

计划：先用合成的索引→快照→浏览器归一化→灯阵链复现，再最小修复图表
对本地/社区两种已存在分桶的识别，补边界、模型与语言回归并定向验证。

## 根因与验收边界

本地分析器及浏览器归一化输出 `one_to_six_hours`、`one_to_three_days`、
`over_three_days`，末桶上界为 null；图表却只接受社区版本中的
`one_to_two_hours`、`two_to_six_hours`、`over_twenty_four_hours`，末桶上界
为604800秒。上方估价可以正常使用，灯阵却因缺桶而拒绝整个结果。

修复须直接画出各自原始分桶，不能把本地1–6小时拆出不存在的样本，
也不能将本地3天以上的证据套用社区7天封顶。混合、未知、缺失分桶和
错误边界仍应拒绝；模型与总样本必须使用同一分桶。

对运行中应用仅只读获取静态资源，确认其 matrix 使用社区桶而 data-client
使用本地桶，没有读取真实用量端点或数据库。运行中资源的修改和应用
生命周期操作均不在本次授权内；源码验证不能替代安装版验证。

## 实现

`apps/web/public/cache-reuse-matrix.js` 按精确键集合选择本地或社区分桶，
每桶继续验证原始上下界、计数分区和总量守恒。拒绝缺失、混合、额外或
未知桶。模型筛选先核对模型与整体分桶的id及上下界，再校验子集计数。
没有修改分析器、原始记录、核算结果或normalizer的本地契约。

`packages/i18n/index.js` 补充本地1–3天及3天以上的三语言短标签，使用
既有生成器更新浏览器镜像；较长的可访问标签复用已有翻译。

## 后续金额核查

用户随后另行允许只读当前应用的内容无关汇总。仅GET已发布overview，
不调用刷新、不读取会话内容或原始数据库、不持久化真实用量样本。
核对选中窗口、已定价小计、排除计数与速度场景；没有确认需要修改的
金额算术缺陷，也没有把未知顺序证据补成零或推算缺失金额。

源码及合成验证确认：金额跟随全局报告窗口；只累计满足严重下降阈值的
已证实缓存前缀损失差价，切换还受五分钟邻近条件限制。压缩、上下文收缩、
无法比较及无法定价分别保留排除或未知状态。顺序缺口按受影响会话计数，
不能将其视为同数量的遗漏请求。已定价小计不受250条详情上限限制。

生产定价、缺失/矛盾输出、超过详情上限的精确累计和分期、前台金额选择
七项定向测试通过；标准与已记录Fast速度及长上下文合成核对未见乘算漏算。
这不能证明未知部分的真实总开销。未扩大算法统计口径；用户指南补充
窗口、半数阈值和差价含义，并修正图表沿用旧分桶说明的文字。

### 后续证据语义更正

上述“已证实缓存前缀损失差价”表述过强。相邻缓存读取计数只能证明
计数变化，不能证明本次可复用前缀C*或可避免损失。随后进行的
[证据与反事实审查](./2026-10-22-cache-evidence-and-counterfactual-audit.md)
纠正此判断：价格算术的定向测试不证明损失可识别性；新的源码把金额
标为条件情景，半数只用于计数分类。此节保留先前核查的时间顺序，
前面的旧门槛与措辞不再描述当前实现。
