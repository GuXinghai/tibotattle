## 状态、范围与依据

已实施源码；构建与本机核对证据见本轮 QA 记录，启动后验收由用户负责。
以本轮确认的头部套餐选择、精简主图和时间对齐交互为展示依据。
预览中的历史 CSV、固定截止点和示例实现不是生产数据源或计算接口。
本文件保留获批的实施契约；测试、真实数据、产物与启动结果分别记录，不互相替代。

保留所有现有未提交修改、原始日志、真实索引和快照。只调整额度页的
周等值 API 展示、必要的区间投影、平滑和联动；不迁移数据库、不重建
账本、不触发全量原始日志扫描，不扩展到其他面板重构或拟合研究。

## 已核对的当前入口

- `apps/web/public/allowance-page.js` 负责额度页布局、明细弹窗、分页和状态保留。
- `apps/web/public/app.js` 向页面提交额度观测、对比曲线点和重置事件。
- `apps/web/public/data-client.js` 负责报告校验、套餐总体选择与历史套餐对比选择。
- `src/local-index-calibration.js` 使用已有历史计价语料生成校准及按套餐隔离的投影。
- `packages/quota-analysis` 通过公共入口提供重置、连续性、套餐归属和校准算法。

当前页面观测与可视化点不足以证明精确区间分子，不能从小时／日汇总、
已拟合容量或画面上采样的曲线点反推本次区间估算。实施时追溯已有
服务端精确证据，复用其定价、归属与去重；必要时在现有报告契约内增加
闭合、有界、版本化的派生区间投影，不默认新增路由或持久化字段。

## 精确区间计算

设区间内 API 等价用量为 C，额度扣减为 d 个百分点：

`整周等值 API = C / (d / 100)`

1. 服务端生成区间。复用现有已确认额度轨道、重置分类、套餐时代和去重
   规则，固定同一报告截止点；不得从旧容量乘百分比反推 C。
2. 使用额度变化的可靠边界。相同读数期间的用量不得因 d 为零而丢失；
   延续到下一次有效变化时仍只计一次。保持明确的区间端点归属规则，
   相邻区间不重复纳入同一用量，边界恰好相等另有测试。
3. 保持单账户、连续订阅的既定分析假设，允许 Plus 与 Pro 之间升级和降级；
   已确认冲突不能被该假设覆盖。按套餐时代、账户证据、额度族、周窗口、
   重置与计价依据隔离，不混合不同来源或重复轨道。
4. 继续使用当前模型、真实速度档、上下文和生效日期对应的 API 计价。
   未确认速度档沿用当前有披露的情景，不偷偷确认成 Standard；未知价格、
   缺少用量或归属不确定要单独标明，不当作零。
5. 自动审查按已确认的免费规则从该额度换算分子中排除，保留原始记录和
   独立用量，不因本次图表改变其他用途的计费或统计。普通响应、压缩调用、
   子任务使用当前可靠去重结果；没有证据的缓存写入不补造。
6. d 为零、负值、跨重置、边界冲突和不完整覆盖不生成伪造容量；保留已
   有效区间，单独标出不可计算区间。真正已证实的零用量与缺失值分开处理。
7. 在完整区间上计算 C/d，再裁切到显示时段。跨显示左边界的区间不按
   可见时长缩放额度分母。最大范围使用全部已发布的有效历史，不偷用 7 天替代。
8. 区间精确分子及分母保留原始精度，最后格式化；显示小数不参与回算。

## 高斯平滑契约

高斯标准差 σ 的单位是分钟，不是区间数，也不是整个窗口宽度。
对每个有效区间 [a_i,b_i) 的常数值 y_i，在时间 t 的核权重为：

`w_i(t) = Φ((b_i-t)/σ) - Φ((a_i-t)/σ)`

`平滑值(t) = Σ(w_i(t) × y_i) / Σw_i(t)`

- 按真实时间积分加权；不按观测密度或区间数量加权，不先复制成等间隔
  用量，也不重新拟合模型成本。
- 居中描述历史曲线，可使用同一报告截止点之前位于 t 两侧的有效区间；
  不用于预测，不能读取报告截止点以后的数据。
- 在完整连续段上计算，再裁切时段。因此同一套餐、同一版本、同一 σ
  下，24 小时和 7 天重叠位置的平滑值一致。
- 不跨套餐、账户证据、重置、计价依据变化或明确覆盖缺口。保留长但
  已确认有效的区间，不另加任意时长阈值将其删除。
- 段首和段尾只用该段现有权重并归一化，不补零、不延伸、不镜像、不用
  另一段填补。新数据发布后边缘值允许正常修订，原始区间不被平滑改写。
- 只有一个有效区间仍可显示其值；没有有效权重显示“—”；非法 σ、非有限
  数值、乱序或重叠不能静默跳过并连成完整曲线。
- 服务端负责原始区间估算，前端仅对已校验结果进行纯展示变换。平滑不
  回写校准、消耗对比、套餐工时、账本、报告或原始观测。
- 数值权重使用稳定 CDF 实现和独立积分对照；结果应处于参与区间值的
  最小值与最大值之间。采样只决定显示精细度，所选时间直接求值。
- 使用固定核精度和有界显示采样／缓存，键按报告版本、套餐、连续段及 σ
  区分；不对所有点和区间反复做无界全积扫描。离线运行，不引入 CDN。

## 数据契约与刷新

- 优先复用已有精确投影；不足时仅扩展现有本地报告的派生字段，包含
  精确时间、C、d、原始结果、连续性、可用性与受控原因。同步闭合 schema、
  validator、浏览器 normalization、类型和版本／兼容策略，不更改原始存储。
- 图、数值、列表、子详情使用同一代报告和计价依据；不拼接不同接口版本。
  套餐切换不发起原始日志扫描，平滑切换不请求新报告。
- 沿用全局每 5 分钟刷新及手动刷新后重新计时；不增加本页计时器。
  现有增量采集继续受批次、字节、时间、取消和恢复边界约束。
- 刷新期间保留同范围旧结果；成功后原子替换区间集合及关联详情，再派生
  平滑显示。报告时间不可因缓存或迟到响应回退。
- 普通刷新保留套餐、σ、用户选中的绝对时间、弹窗、分页和滚动。原来在
  最新位置时跟随最新有效位置；用户已回看历史则不强制跳到末尾。
- 套餐或报告时段切换关闭旧详情并取消／隔离旧请求。保存各时段平滑偏好；
  不将历史套餐空状态解释成当前套餐失败。
- 重试显式有界；同一次刷新和读取去重。正常取消不报失败，也不发布半份结果。

## 错误与缺失状态

分别处理请求失败、超时、解析失败、结构／范围／来源校验失败、报告过期、
索引／计价／区间投影失败及平滑／绘图失败。复用已有分类，新增原因采用
受控闭合码，不投影原始路径、日志、账户标识或堆栈。

- 主页面异常时提供简短类别和重试；详情提供代码、阶段、报告结果时间。
- 同范围旧结果保留时标记更新失败或过期；来源不匹配的结果不作为该范围
  的可用旧结果。不能删除快照或跳过来源校验来恢复画面。
- 无记录、只有观测无配套用量、个别区间不完整、未计价和取消各自呈现；
  不与异常或零值混淆。有数据的区间继续显示，缺口原位保留。
- 平滑失败仍可使用经验证的原始区间，但必须明确平滑失败；不得悄悄
  切回原始曲线却保留“平滑”状态，也不得让该异常清空其他面板。

## 实施顺序与验证

1. 对照当前可用投影，锁定区间、连续段、套餐、计价和报告版本契约；
   用合成结构证明平台期不漏计、精确端点不重复、重置不跨越。
2. 在现有服务端报告流程实现最小派生投影及闭合校验，不改原始记录；
   保留现有边界、取消、恢复、去重和快照隔离测试。
3. 实现独立可测的展示平滑，再改主页面、头部套餐选择、对齐滑条和完整
   详情。保留其他面板及额度旧分析入口。
4. 更新 canonical 翻译并生成浏览器镜像；同步当前维护的 API、组件、
   校准说明及资源清单，不手改生成文件。
5. 先执行受影响测试：精确区间、重复读数、缺失、跨重置、套餐切换、
   自动审查排除、普通／压缩响应去重、速度档、计价边界和最大历史范围。
6. 平滑测试覆盖常数保持、不等时长权重、单区间、端点、缺口、重置、
   各 σ、独立积分核对、有限值／值域及不同显示范围的重叠一致性。
7. 交互覆盖所有时段／套餐／平滑选项、精确时间和竖线与滑块像素对齐、
   全分页、返回／焦点、刷新保留、旧响应隔离、旧结果保留、局部错误、
   深浅色／系统主题与 320／390／736 像素和桌面宽度。
8. 运行一次 UI 门禁；如扩展报告契约，运行本地服务门禁及契约测试；
   如改动 quota-analysis，按该目录要求运行根测试和架构检查。
   运行翻译、资源闭包、文档和必要 preflight。失败先分类诊断，不放宽
   安全检查或为测试通过改变计价语义。
9. 在真实数据的同一发布截止点，只读核对全部有效区间：数量、边界、C、
   d、计算值、排除原因及套餐分组。分子与已去重用量对账；跨范围对比
   同一 σ 的同一时间点；缺失用独立合成测试补充，真实数据不写入夹具。
10. 使用内置浏览器核对真实数据的主图和完整详情，报告证据边界。后续
    打包时使用规定 Node.js 26.2.0 的正常 Windows 候选、保留上版产物；
    如进入启动交付阶段，按既定安排使用正常真实配置，启动后验收交由用户，
    不擅自增加持续监控或用隔离数据替代真实数据验证。
