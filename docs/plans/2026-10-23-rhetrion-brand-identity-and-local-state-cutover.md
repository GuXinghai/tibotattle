# 目标架构

## 稳定身份、品牌与分发分离

沿用现有 config 边界拆分职责，不新增根目录，不在网页、桌面和脚本各维护一份身份常量。
建议增加 `config/application-identity.cjs` 作为稳定身份的规范定义，供 CJS 打包配置和 ESM 组合根消费；
浏览器或隔离桌面代码按现有构建、生成边界取得需要的公开子集，不绕过包或运行时边界。
`config/product-brand.js` 只保留展示定义；分发配置继续由现有分发所有者管理。

| 项目 | 目标约定 |
| --- | --- |
| 主程序内部 App ID | 保留 `com.usagemonitor.local`，不随展示名称变化 |
| 包与 CLI | 保留 `app-usagemonitor` 和 `usage-monitor` |
| 程序文件名 | 固定 `usage-monitor.exe`，不根据品牌推导 |
| 本地协议 | 保留 `usagemonitor://open`；其他内部协议与 IPC 使用同一中性命名空间及独立格式版本 |

| 数据目录 | 在 Windows appData 下固定 `UsageMonitor/profiles/<profile>`；不使用展示名称、工作目录或可执行文件名推导 |
| Electron 会话与持久资源 | 启动创建会话、数据库或窗口之前确定其根路径；companion 显式取得同一 profile 对应的数据根 |

| 品牌资源 | 使用中性的 `app-icon.svg`、`app-icon.png`、`app.ico` 和独立托盘资源命名 |
| 分发 | 下载包显示名、更新源、支持地址、签名身份单独配置，不能成为存储或业务身份 |

正式与开发 profile 均由受信任的组合根选择并校验，不接受任意 renderer 路径或 profile 输入。
桌面可从品牌配置取得显示名，但不能再用 app.getName() 的展示结果判定生产权限。
替代检查必须继续绑定已打包状态、内部身份、目标平台、分发元数据及现有制品验证，
不能通过移除名称判断而削弱原来的拒绝条件。

格式版本归属数据合同。旧品牌格式到中性格式的转换需要明确源版本、目标版本、转换规则和目标验证器；
不把新格式重新命名成旧版本，不降低数据库版本，不把 SQLite user_version 改号当作迁移。
与品牌无关的数据合同不作顺手改版。未来真正的数据结构演进仍需要正常的向前迁移。

旧目录、旧格式解释和旧名称映射只存在于独立的本机一次性迁移包及其 owner-only 清单中，

# 一次性迁移合同

## 范围、备份与转换

1. 先只读确认实际源和目标的绝对路径、profile、所属应用、文件身份、ACL、链接状态和剩余空间。
   多个候选源不能按修改时间或体积猜选；目标已存在时拒绝覆盖，除非证明属于同一迁移的恢复。
2. 明确列出用量 bundle 的数据库及旁路文件、断点、原盐、计时、计算基线、已有用量快照、
   必要数据源/观测控制，以及含唯一历史的旧用量证据。X/UI/浏览器等排除范围不递归读取或迁移。
   不改动被监测应用的原始会话目录，不扩大源数据采集范围；未知的 bundle 依赖仍阻断。
3. 正常停止能够修改此 bundle 的写入者并确认释放锁；SQLite 采用可证明一致的冷备或官方备份机制，
   不只复制正在写入的主库。残留 WAL/SHM 或热日志先按一致性流程处理，无法确认则停止。
4. 在 owner-only 备份根中保存完整用量恢复包、清单和摘要，验证备份可读、数据库完整性及依赖覆盖。
   不迁移或读取 X/Chromium 密文，不读取或打印 cookie、密钥、原始账户标识；凭据存储不导出或轮换。
5. 从备份复制到独立暂存区，只对明确允许的自有数据结构做转换；未知版本、未知必要文件或损坏数据
   阻止切换。不能遍历字符串全局替换，也不能把“可重新计算”作为丢弃已保留证据的理由。
6. 校验无需转换的文件摘要；对转换对象用规范验证器和语义对账，不以字节相同作为目标。
   历史计数、归属边界、累计值、断点、速度基线和必要数据源/观测控制保持原有含义，不能重放后重复计数。
   未选中的隐私选择与退休记录继续保留在源，不恢复已移除的分享功能。
7. 在对应 Windows 运行环境验证用量冷重开、数据源与账户归属连续性。X 登录/缓存/通知/导入状态
   不承诺延续，也不作为失败门；不能借此清除旧会话、隐式登录或重注册 helper。

当前的 Windows legacy continuity copy 是固定范围的旧流程，不是显式用量 bundle 选择器，
不能直接整包调用并额外复制无关状态。沿用平台公共入口和安全原语；不以 Node 普通文件权限检查替代原生边界，
也不修改原生资格标志来使迁移通过。

## 日志、激活与恢复

持久操作日志采用独立中性合同，至少区分
`prepared → backed_up → converted → verified → activated → accepted`。
每个状态绑定同一操作、源文件身份、备份摘要、候选制品和目标位置，写入顺序及中断点可验证。
私有路径及逐文件清单只在 owner-only 本机材料内；终端、诊断和仓库仅保留不含内容的状态摘要。

激活前旧源保持权威；新候选的验收启动通过显式隔离入口选择目标，不能自动改写旧源。
激活使用目标文件系统支持的单项原子切换加持久日志，只影响显式用量目标，禁止整份 profile 覆盖或恢复。
不声称目录、注册表、快捷方式和凭据能作为跨资源原子事务完成；其他启动入口与系统集成另行验证，
不改写 X helper 注册或凭据来使本次迁移通过。
存在旧进程、锁冲突或未完成迁移时，新程序不得作为空白 profile 继续写入。

重复执行只恢复同一操作或报告已完成，不重新导入、不双写、不自动把旧目录重新视为有效源。
切换前失败保留旧源与备份；切换后恢复必须先停止新写入并归档新增目标数据，再恢复绑定的快照，
不得直接覆盖新增历史。恢复也是显式操作，拒绝损坏备份、错误目标、跨 profile 或未知较新格式。
本次验收不自动删除旧目录；后续删除需要独立的精确目标和授权。
