# 已验证的问题与试算边界

- 当前 `analyzeWorkload` 每次接受余额相同的读数，都会推进分摊起点；真实记录中多个
  Codex 会话交错写入读数，使部分下降区间缩短至毫秒，区间内没有正用量而被列为未分类。
- 历史日柱的重置键使用精确截止时间，秒级抖动会断开配对；启动比较已有另一段按证据
  识别周周期的逻辑。应在概览分析内部复用周期机制，不能再增加独立阈值和第三套判断。
- 合成测试确认：跨天区间缺少可分摊用量时，已知消耗未进入任何日柱；同一案例的区间
  消耗为 1 个百分点，日柱合计为 0。此为边界复现，不是已证实的真实跨天缺失清单。
- 当前七天结果有 3 条无法确认模型的用量；不能因减少黑块而猜测模型或价格。
- 同一索引代次的只读主规则试算中，10 月 19 日未分类由 2 降至 0 个百分点，
  10 月 20 日由 11 降至 1 个百分点，当日占比约由 52.4% 降至 4.8%。
  试算未完成周期、跨天、读取边界和守恒修复；数字仅作回归比较，不作为最终必须达到的值。

# 确定采用的处理口径

## 1. 以首次观察到新余额建立区间

- 每个连续额度周期的首个有效读数只建立基线，不推算此前消耗。
- 余额相同的后续读数更新观测新鲜度，不移动分摊起点。
- 第一次读到更低余额时，闭合 `(起点, 本次时间]`，消耗为两端余额之差；
  以本次时间和余额建立下一起点。一次下降多个百分点直接按实际差额处理，不虚构中间时间。
- 该区间内所有有效本地用量都参与既有权重分摊；并行会话的额度读数共用同一周期起点，
  不各算一份账户额度。继续复用已有用量去重和任务时间并集，不引入第二本账。
- 重复输入、输入乱序、迟到记录及重复刷新得到确定结果；新补到的历史记录可重新计算
  展示归属，但不得修改原始观测，也不得重复累计。
- 同一周期中余额回升的迟到旧读数不能回退起点；已退役周期的迟到读数不能重开旧周期。
- 同一时刻出现无法消解的不同读数时不任意挑选，保留冲突并切断该处配对。
  冲突后的首个可靠读数重建基线，不借用冲突两侧的差额。

## 2. 周期、套餐与身份边界

- 将 `workload.js` 内现有周周期识别逻辑提取为一个窄内部函数，供历史区间和启动比较
  复用。启动比较继续使用原来的严格身份、直接观测及累计口径，不改用历史分摊起点。
- 复用现有 5 分钟截止时间不确定性预算、周窗口约束与已校验重置事件；不因截止时间
  相差 1 秒就拆周期，不仅凭余额回升就认定重置，也不以滚动邻近匹配无限漂移截止锚点。
- 真正到期、新周期、已确认的提前重置、账户切换和套餐时段切换均建立新基线；
  无法确认的过渡保持断点，不跨越补算。额度重置记录的读取范围覆盖历史分析所需区间。
- 原始缺少身份或套餐的证据只沿用已批准的推定范围，不新建身份推定；一旦显式冲突
  或身份变化即停止连续性。不同套餐的百分点始终分开汇总。
- 不改动其他报表、校准或采集层的周期契约，不为此次概览修复统一全仓额度架构。

## 3. 分档、缺价与跨天

- 保留现有五分钟负载桶、近七天聚类和 API 等价计价权重；不改模型价格、速度假设
  或轻中重的定义，不按 Token 数量或经过时间新增回退权重。
- 区间用量计价完整且权重为正时，按已有用量权重分配额度；每份落到该用量在设备时区
  对应的日期和负载档位。区间跨天时可调整两天柱高，不能把整段记在结束当天。
- 区间存在无法计价的正用量时，已知消耗整体保留为未分类，不能将未知权重视为零，
  再把全部额度分给已知部分。保留缺价原因和既有可安全显示的诊断。
- 区间有可定日的用量但任务边界不足、桶无法分档或聚类不可用时，仍保留可定日的
  未分类消耗；不能把缺任务记录误写为没有使用。
- 无法可靠分配到日期的区间：若两端在同一本地日期，保留为当天未分类；若跨天，
  保留起止时间、套餐、总百分点及缺失原因，进入独立的“跨天未分配”集合。
  有日期但缺金额权重的记录也不构成可靠的跨天比例。
- 已知日分摊、同日未分类和跨天未分配互斥；每份消耗只能进入其中一处。无法比较的
  不同套餐不得相加成一个可比较的总百分点。

## 4. 跨天未分配信息放在概览最下面

- 按用户最新要求，位于全部概览卡片与现有诊断之后，属于概览内容末尾；不放在
  额度消耗图下方，不在侧栏、其他页面或悬浮窗口增加入口。
- 无跨天未分配记录时不占空间；有记录时显示紧凑的可展开区域，标题为“跨天未分配”。
  折叠态按套餐展示总量和区间数，展开查看时间区间、套餐、百分点和简短原因。
- 展开明细最多投影 20 条；超过时明确显示未展示条数，汇总仍覆盖完整集合。
  不为截断的明细丢弃数据或把它们算成零，不新增分页 IPC 或设置项。
- 采用现有黑灰文字、无多余底色和布局规则；窄窗口允许换行、保留键盘展开操作。
  日期和时区由现有格式化机制统一处理。

## 5. 尚未闭合的区间与工时

- 最新起点之后、尚未再次观察到下降的用量属于待闭合尾段，不生成已确认的消耗，
  不以零消耗纳入历史消耗速率，也不凭近期 API 等价金额补造百分比。
- 已闭合区间才参与对应的剩余工时估算；额度分子和工作时间分母必须来自同一组
  可用区间、同一套餐时段。无完整计价或任务时间依据的区间不污染对应分档速率。
- 综合工时继续保留既有“实际额度变化／有效任务时间”的独立口径，不要求模型计价
  才能使用；但任务时间不完整、冲突或套餐不兼容时必须排除该区间的分子和分母。
- 长时间空闲不算工作时间；并行任务仍只计一次。当前负载的十五分钟算法不因历史
  分段变更而改变，无足够样本时继续显示不可用。
- 待闭合尾段不作为跨天未分配消耗展示；后续下降闭合时正常回算此前日期。

# 读取、缓存与兼容性

- 先识别与显示区间相交的完整消耗区间，再读取各区间起点所需的前驱观测和用量；
  不先裁剪七天数据再寻找起点。保留“最近七个本地日期”的日柱范围和现有滚动聚类范围。
- 完整区间中显示范围外的用量仍参与分母，随后才裁剪展示；禁止把范围外的消耗
  挤到范围内。跨时区和夏令时按实际本地日期边界处理，不假定每天固定 24 小时。
- 通过有界、可取消的读取和现有来源证明取得必要上下文，处理任务跨边界的工时证据。
  不扫描所有历史来找起点；找不到前驱或达到现有资源边界时明确标为覆盖不足，
  不用截断记录冒充完整区间。读取失败保留最后成功结果并标记陈旧。
- 区间由已保留的事实确定性重建，不为起点新增独立持久状态或数据库表；重启、缓存
  清理和七天范围移动不能改变同一完整证据集的分段结果。只读分析不调用索引刷新或恢复。
- 复用现有有序用量索引、前缀和或单次遍历完成权重与时间查询；聚类只处理原有范围。
  不为每个读数重扫用量或重复聚类，不增加全局刷新协调器和后台定时器。
- 结果契约前进到 `overview-workload-v5`，分段策略前进到 `task-workload-v7`，增加
  闭合区间覆盖／守恒摘要及有界的跨天未分配汇总和明细。同步公开类型、校验、消费者
  和夹具；前端继续读取旧 v2–v4 快照，新语义仅由 v5 结果声明。
- 新字段只含闭合的安全枚举、时间、套餐、数量和百分点，不传账户句柄、来源路径、
  会话 ID 或原始记录；畸形值拒绝，未知版本不伪装成有效零值。
- 旧快照可先作为陈旧结果展示，下次现有刷新重算后整体替换；禁止把旧策略的日柱与
  新策略的未分配汇总混合。策略版本进入所有相关复用条件，不改 SQLite schema、
  不重标历史版本、不擦除应用数据，也不迁移无变化的启动比较持久状态。

# 实施位置与顺序

1. `packages/quota-analysis/src/workload.js`：提取周周期机制，建立首次变化区间，
   实现互斥分配、未闭合尾段及工时覆盖；通过包入口同步类型及必要导出，不暴露私有路径。

3. `apps/web/public/overview-workload.js` 及确有需要的现有样式：规范化 v5，
   将跨天未分配区域放在整个概览末尾。前端只渲染结果，不另写分段或末端判断。
4. 更新拥有这些契约的测试、`packages/quota-analysis/index.d.ts`、
   [用户指南](../user-guide.md)、[索引契约](../reference/local-index-schema.md)及套餐推定决策。
   如增加文案，只改 canonical i18n 并运行既有生成器，不手改浏览器或 Electron 镜像。
5. 对照测试后做真实历史只读回放和范围验证；记录实施与未覆盖门，不顺带修模型识别、
   调整全局计价，或修改其他正在进行的工作。

# 验证与验收

仅运行下列最小相关验证，不运行全量测试或完整产品门。

| 范围 | 必须覆盖的结果 |
| --- | --- |
| 分段 | 相同余额不推进起点；首次下降闭合；多百分点跳变；多会话交错；重复、逆序、迟到、同刻冲突；输入不变 |
| 周期 | 秒级抖动保持周期；固定锚点防累积漂移；真到期和提前重置切断；旧周期不复活；未知过渡不跨接 |
