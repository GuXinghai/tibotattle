## 范围与验收

修复 [已确认的压缩发现缺口](../reports/2026-10-17-timing-compressed-discovery.md)。
保留原始日志、压缩文件、真实用量账本和其他未提交工作。只更新计时派生状态；
沿用原逻辑来源及轮次身份，不能将压缩表示另计一次。启动后验收交给用户。

## 实施

1. 发现 `.jsonl` 和 `.jsonl.zst`，同一逻辑路径优先未压缩表示；发现集合与
   索引使用同一逻辑路径规范。保留目录、条目数、原生权限及链接边界。
2. 复用有界 Zstd 验证器，流式读取逻辑字节。主／补充计时共享解码窗口；
   每次只解析受限切片，不落地解压正文，不因每个切片从头解压。
3. 复用原有暂存、去重及原子发布。保存逻辑游标、解析状态、物理压缩来源
   快照和完成状态；重启后最多恢复解码到已提交游标，不重复计入旧轮次。
   未变化且完成的压缩来源只核对元数据，不重新解压。
4. 压缩语义需要前向 schema 边界，旧写入器必须拒绝新状态；不提升全局
   计时解析版本，不触发其他未变化来源的历史重扫。
5. 来源变化、解码／格式错误、读取拒绝、资源上限、缺失和取消分别处理。
   未完成或失败保留旧测量，不把损坏输入发布为完整结果。

## 验证与交付

合成覆盖未压缩／压缩共存、表示切换、主补去重、分批及重启恢复、EOF、
截断／损坏、取消、源变化、边界限制和完成后零解压。运行受影响测试、
本地服务与必要 UI／翻译／架构门禁。真实计时库只读备份后在受保护副本
验证；真实记录不进入夹具。核对待恢复来源、轮次、主补关联、重复刷新
工作量及未受影响数据。最后用 Node.js 26.2.0 打包新的 Windows 候选，
保留旧程序，校验产物，以正常真实配置启动，不代替用户做启动后验收。

源码及真实副本验证见 [验证记录](../qa/2026-10-17-compressed-timing-recovery.md)。
